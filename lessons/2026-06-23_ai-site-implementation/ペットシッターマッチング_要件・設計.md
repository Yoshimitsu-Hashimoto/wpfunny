## 1. プロジェクト概要

### 1.1 背景・目的

ペットを預けたい飼い主と、ペットシッターをつなぐマッチングサイトを WordPress でゼロから構築する。クラウドソーシングのように決済や仲介まではやらず、両者が直接つながる"きっかけの場"を提供する。

本サイトは WordPress 講座のデモ案件として位置づけ、実際の開発フローや設計判断を学習材料として活用する。

### 1.2 スコープ（対象外の明示）

| 項目 | 対象外 |
|---|---|
| 決済機能 | シッターと飼い主が直接決済するため対象外 |
| チャット・メッセージ機能 | フォーム経由の連絡のみ |
| 予約管理 | 対象外 |
| スマホアプリ | レスポンシブ対応のみ |
| レビューの不正検知 | 運営が目視確認（自動検知なし） |

### 1.3 制約・前提条件

- WordPress（最新安定版）で構築
- ホスティング環境は PHP 8.1 以上、MySQL 8.0 以上を想定
- テーマはブロックテーマまたはクラシックテーマ（講座内で選定）
- メール送信は WP Mail SMTP を使って安定化する
- サイト言語：日本語

> ⚠️ **確認事項**：問い合わせ履歴で管理画面に表示するフィールドの範囲（「誰が誰に」のみか、全内容を含むか）が未確定。本書では全フィールドを表示する前提で設計する。要件確定後に修正すること。

### 3.4 飼い主が依頼を掲載する（F-07 / F-08 / F-09）

#### 投稿フォーム（F-07）

| フィールド | 種別 | 必須 |
|---|---|---|
| 投稿者名 | テキスト | ○ |
| メールアドレス | メール（非公開・トークンURL送付先） | ○ |
| ペットの種類 | テキスト | ○ |
| 頭数 | 数値 | ○ |
| 預けたい期間（開始日） | 日付 | ○ |
| 預けたい期間（終了日） | 日付 | ○ |
| 掲載期限 | セレクト（72時間・1週間・2週間・30日） | ○ |
| プライバシーポリシーへの同意 | チェックボックス | ○ |

#### スパム対策：メール認証方式（F-07）

- 投稿フォーム送信後、即座には公開しない
- `draft` 状態で `pet_request` CPT に仮保存
- 確認メールに「認証リンク」と「管理用トークンURL」の2つを記載して送信
- 認証リンクをクリックした時点で `publish` に変更・掲載開始
- 認証リンクは72時間で失効（失効した場合はそのまま `draft` のまま）

#### 掲載期限管理（F-08）

- 掲載期限 = 投稿日時 + 飼い主が選択した時間（72時間〜30日）
- WP Cron が1時間ごとに期限切れの `publish` 投稿を検出
- 期限切れを検出したら `post_status` を `draft` に変更
- `draft` になると一覧・詳細ページどちらも非表示になる
- 期限は「残り時間」ではなく「期限日時」として詳細ページに表示

#### 投稿者による確認・削除（F-09）

- 確認メールに記載の管理用URLにアクセスすると依頼の内容確認と削除ができる
- URLは `?action=view&token=xxx` 形式
- 削除は物理削除ではなく `draft` への変更（内部的に保持）
- トークンは `bin2hex(random_bytes(32))` で生成し ACFフィールドに保存

#### 運営による管理

- 管理画面から任意の投稿を下書きに変更することで即座に非表示
- 専用の管理ページは不要（標準のカスタム投稿管理画面を利用）

### 3.6 評価システム（F-11 / F-12）

#### 評価フォーム（F-11）

| フィールド | 種別 | 必須 |
|---|---|---|
| 評価者名 | テキスト | ○ |
| 評価者メールアドレス | メール（重複防止・不正抑止用） | ○ |
| 評価（星の数） | ラジオまたはセレクト（1〜5） | ○ |
| コメント | テキストエリア | 任意 |
| プライバシーポリシーへの同意 | チェックボックス | ○ |

#### 評価の反映（F-12）

- フォーム送信後、運営の承認ステップなしで即時反映
- カスタムテーブル（`wp_pet_reviews`）に保存
- 保存後に当該シッターの評価平均を再計算
- 計算結果（`rating_average`・`rating_count`）を `sitter` の `post_meta` に保存（キャッシュ）
- 一覧・詳細ページは `post_meta` の値を読むだけ（毎回集計しない）

> 💡 評価フォームはシッター詳細ページ下部に設置。または「評価を投稿する」ページを別途用意してもよい。

## 4. 法的対応

### 4.1 必要ページ

| ページ名 | スラッグ | ステータス |
|---|---|---|
| 特定商取引法に基づく表示 | `/tokushoho` | 必須 |
| プライバシーポリシー | `/privacy` | 必須 |
| 利用規約 | `/terms` | 必須 |

- 全3ページをフッターに常設リンクとして配置
- 利用規約には「本サービスは場を提供するのみで当事者間トラブルに責任を負わない」旨を明記
- 利用規約には「シッターは動物取扱業登録の必要性を自身で確認すること」を明記

### 4.2 フォームへの対応

| フォーム | 同意チェックボックス | 未チェック時 |
|---|---|---|
| シッター登録フォーム | 利用規約・プライバシーポリシー（各個別） | 送信不可 |
| 問い合わせフォーム | プライバシーポリシー | 送信不可 |
| 依頼投稿フォーム | プライバシーポリシー | 送信不可 |
| 評価フォーム | プライバシーポリシー | 送信不可 |
| 応募フォーム（依頼詳細） | プライバシーポリシー | 送信不可 |

### 4.3 動物取扱業について

- ペットシッター業は都道府県への「第一種動物取扱業（保管）」登録が必要な場合がある
- これはシッター個人の義務であり、本サイト運営者の義務ではない
- シッター登録フォームに「動物取扱業登録の有無」フィールドを設ける
- 登録番号をプロフィールページに表示できるフィールドを用意する

## 5. データ設計

### 5.1 全体構成

| データ | 保存方式 | 理由 |
|---|---|---|
| シッタープロフィール | カスタム投稿タイプ（`sitter`） | コンテンツとして一覧・詳細ページが必要 |
| 預かり依頼 | カスタム投稿タイプ（`pet_request`） | 公開・下書き制御・Cron処理が必要 |
| 問い合わせ履歴 | カスタムテーブル（`wp_pet_inquiries`） | トランザクションデータ・`wp_posts` に混入させない |
| レビュー | カスタムテーブル（`wp_pet_reviews`） | シンプルな構造・集計が容易 |
| 評価平均・件数 | `post_meta`（`sitter`） | レビュー保存時に計算してキャッシュ |
| シッター属性 | ACF（`post_meta`） | 管理画面から直感的に操作できる |
| 依頼の付加情報 | ACF（`post_meta`） | トークン・期限・メールなどを保存 |

### 5.4 カスタムテーブル

| カラム名 | 型 | 内容 |
|---|---|---|
| `id` | `BIGINT UNSIGNED AUTO_INCREMENT PK` | 主キー |

| `sender_name` | `VARCHAR(100) NOT NULL` | 飼い主の名前 |
| `sender_email` | `VARCHAR(200) NOT NULL` | 飼い主のメール |

```sql
CREATE TABLE wp_pet_inquiries (

    sender_email VARCHAR(200)    NOT NULL,
    pet_type     VARCHAR(100),
    period       VARCHAR(200),
    message      TEXT,
    agreed       TINYINT(1)      DEFAULT 0,
    created_at   DATETIME        DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### `wp_pet_reviews`（レビュー）

| カラム名 | 型 | 内容 |

```sql
CREATE TABLE wp_pet_reviews (
    id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    sitter_id      BIGINT UNSIGNED NOT NULL,
    reviewer_name  VARCHAR(100)    NOT NULL,
    reviewer_email VARCHAR(200)    NOT NULL,
    rating         TINYINT UNSIGNED NOT NULL CHECK (rating BETWEEN 1 AND 5),
    comment        TEXT,
    created_at     DATETIME        DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6. システム構成

### 6.1 使用プラグイン

| プラグイン | 役割 | 選定理由 |
|---|---|---|
| Advanced Custom Fields (ACF) | カスタムフィールド管理 | 直感的な管理UI・表示関数が豊富・無料版で十分 |
| Contact Form 7 | フォーム作成（問い合わせ・評価・応募） | 軽量・カスタマイズ性高・`wpcf7` フックが豊富 |
| WP Mail SMTP | メール送信の安定化 | WordPress デフォルトのメール送信は不安定 |
| User Role Editor | シッターロールの権限設定 | 管理画面から権限を細かく制御できる |
| reCAPTCHA for CF7 | フォームへのボット対策（前段） | メール認証の前段でボット排除・CF7と連携可能 |

> 💡 依頼投稿フォーム・シッター登録フォームはプラグインでは要件を満たせないためカスタム実装（`functions.php` またはカスタムプラグイン）する。

## 7. 主要処理フロー

### 7.1 依頼投稿フロー（F-07〜F-09）

```
① フォーム送信
      ↓ バリデーション・reCAPTCHA確認
② draft 状態で pet_request CPT を wp_insert_post() で仮保存
      ↓
③ bin2hex(random_bytes(32)) でトークン生成 → ACF に保存
      ↓
④ 現在時刻 + 選択時間 → listing_expires_at に保存
      ↓
⑤ 認証URL + 管理URLを記載した確認メールを送信
      ↓
⑥ 認証URL（?action=verify&token=xxx&id=xxx）をクリック
      ↓ トークン照合 → is_verified = true → post_status を publish に変更
⑦ 一覧・詳細ページに掲載開始
      ↓
⑧ WP Cron（毎時実行）が listing_expires_at を過ぎた publish を検出
      ↓ post_status を draft に変更
⑨ 一覧・詳細ページから非表示（内部的にはデータ保持）
```

確認メールに含める内容：

- 認証リンク：`?action=verify&token={token}&id={post_id}`（有効期限：72時間）
- 管理リンク：`?action=manage&token={token}&id={post_id}`（確認・削除）

### 7.2 評価平均の計算ロジック（F-12）

計算タイミング：**評価フォーム送信直後**

```
① CF7 の wpcf7_mail_sent フック発火
      ↓
② wp_pet_reviews テーブルに INSERT
      ↓
③ 該当 sitter_id の全レビューを SELECT で集計
   → AVG(rating) と COUNT(id) を計算
      ↓
④ update_post_meta() で rating_average・rating_count を sitter CPT に保存
      ↓
⑤ 一覧・詳細ページは get_post_meta() で取得するだけ（毎回集計しない）
```

一覧での評価順並べ替え（WP_Query）：

```php
$query = new WP_Query([
    'post_type' => 'sitter',
    'meta_key'  => 'rating_average',
    'orderby'   => 'meta_value_num',
    'order'     => 'DESC',
]);
```

### 7.3 問い合わせフォームのフロー（F-03）

```
① CF7 フォームにhiddenフィールドでシッターの CPT ID を埋め込む
      ↓
② wpcf7_mail_sent フック内で $wpdb->insert() により wp_pet_inquiries に INSERT
      ↓
③ wp_mail() でシッターのメールアドレスに通知
      ↓
④ 同じく運営メールアドレスにも wp_mail() で CC 送信
```

### 7.4 シッター登録後の自動処理（F-10）

```
① ユーザー登録完了
      ↓ user_register フック発火
② WP_User->set_role('sitter') でロールを sitter に変更
      ↓
③ wp_insert_post() で sitter CPT を draft で自動作成
      ↓
④ 管理者が確認後に手動で publish に変更
      ↓
⑤ シッタープロフィールが公開
```

## 8. 実装フェーズ

| フェーズ | タスク | 対応機能 |
|---|---|---|
| **Phase 1**（基礎構築） | CPT・Taxonomy・ACF 定義<br>シッター一覧・詳細テンプレート<br>ユーザーロール設定 | F-01, F-02, F-10（登録のみ） |
| **Phase 2**（問い合わせ） | `wp_pet_inquiries` テーブル作成<br>CF7フォーム設置<br>管理画面カスタムページ | F-03, F-04 |
| **Phase 3**（依頼掲載） | フロントエンド投稿フォーム実装<br>メール認証フロー<br>トークンURL処理<br>WP Cron 期限管理 | F-05, F-06, F-07, F-08, F-09 |
| **Phase 4**（評価・法的対応） | `wp_pet_reviews` テーブル作成<br>評価フォーム・計算ロジック<br>法的3ページ作成<br>フォームの同意チェックボックス追加 | F-11, F-12, F-13 |

> 💡 Phase 1 → Phase 4 の順に進めることで、各フェーズ完了時点でデモ・動作確認ができる構成になっている。

### 実装上の注意点

| 項目 | 注意点 |
|---|---|
| フロントエンド投稿 | nonce・capability チェックを必ず実装すること |
| トークン生成 | `bin2hex(random_bytes(32))` を使用。`wp_generate_password()` でも可 |
| メールアドレスの保護 | `requester_email` は ACF の「管理者のみ表示」設定を活用 |
| WP Cron の信頼性 | 本番環境では `wp-cron.php` の外部呼び出しを無効化し、サーバーの cron で代替を推奨 |
| `$wpdb` の利用 | カスタムテーブルへのアクセスは必ず `prepare()` でエスケープ |
| テーブル作成タイミング | `register_activation_hook` でプラグイン有効化時に `dbDelta()` で作成 |

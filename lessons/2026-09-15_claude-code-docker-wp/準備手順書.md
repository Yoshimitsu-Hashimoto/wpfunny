wpFUNNY ライブ講座「Claude Code と Docker で WordPress ローカル環境を作る」（シリーズ第1回）
講師 PC を本番の状態に整えるための、一度きりの作業。

- 講座日: 2026-09-15
- 対象 PC: Mac（Apple Silicon）
- 親ディレクトリ: `/Users/yoshio/work/wp-local`
- 所要: 30〜60分（イメージの pull に時間がかかる）

## 1. Docker Desktop を入れる

1. https://www.docker.com/products/docker-desktop/ から **Apple Silicon 版** をダウンロード。
   Intel 版を落とすと動かない。
2. `.dmg` を開いて Applications にドラッグ。初回起動で規約に同意し、パスワードを求められたら入力。
3. メニューバーのクジラアイコンが「Docker Desktop is running」になるまで待つ。
4. Docker Desktop の Settings → Resources で、メモリを **4GB 以上** にしておく。
   WordPress + MySQL の2コンテナを同時に動かすのに余裕がいる。
5. Settings → General の **「Start Docker Desktop when you sign in」をON**。
   当日「Docker が起動していなくてコマンドが全部こける」事故を防ぐ。

> 当日の朝、必ずクジラアイコンが緑になっていることを目視確認する。

**ここまでOKの確認コマンド**

```bash
docker run --rm hello-world && docker compose version
```

## 2. Claude Code を入れて認証する

導入済みなら 3 に飛ぶ。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Node.js は不要。`~/.local/bin/claude` に入る。PATH が通っていなければ:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
```

ターミナルを開き直してから `claude` を実行するとブラウザが開いて認証に進む。

> `npm install -g @anthropic-ai/claude-code` でも入るが、Node.js が必要。
> 上の native installer なら Node 不要で済む（約210MB のダウンロード）。

当日のための設定:

- 認証は**前日ではなく当日の朝**に一度 `claude` を起動して通ることを確認する（セッション切れ対策）。
- ターミナルのフォントサイズを **16pt 以上**に上げる。Zoom の画面共有で読めない事故が一番多い。
- ターミナルの配色はライトテーマ推奨。ダークテーマは Zoom 圧縮で潰れやすい。
- 通知・Slack・メールを切る。共有画面に出る。

**ここまでOKの確認コマンド**

```bash
claude --version
```

## 4. イメージを事前に pull しておく

本番で初回 pull を待つと 3〜5分沈黙する。前日に必ず落としておく。

```bash
docker pull wordpress:6.8-php8.3-apache
docker pull mysql:8.4
```

さらに、WP-CLI 入りイメージのビルドも一度通しておく（apt と phar のダウンロードがキャッシュされる）:

```bash
cd /Users/yoshio/work/wp-local
./scripts/new-env.sh warmup 8090
cp examples/{compose.yml,Dockerfile} warmup/
cp examples/.env.example warmup/.env
cd warmup && sed -i '' 's/"8080:80"/"8090:80"/' compose.yml
docker compose build
cd .. && ./scripts/reset.sh warmup -y && rm -rf warmup
```

### Apple Silicon の注記

- `wordpress:6.8-php8.3-apache` と `mysql:8.4` はどちらも arm64 イメージがある。そのまま動く。
- arm64 が無いイメージ（古い `mysql:5.7` など）に差し替える場合は、そのサービスに
  `platform: linux/amd64` を書く。エミュレーション動作になり、目に見えて遅くなる。
- 当日、AI が `platform:` を勝手に足してきたら「arm64 があるので不要」と指摘して外させる。
  デモの見せ場になる。

**ここまでOKの確認コマンド**

```bash
docker images | grep -E 'wordpress|mysql'
```

## 5. Before 用の素の領域を用意する

PART 1（素のまま作る）は、**`wp-local` の外**でやる。

```bash
mkdir -p ~/work/wp-plain
```

> **必ず `wp-local` の外に置くこと。**
> Claude Code は親ディレクトリを遡って `CLAUDE.md` を読む。`wp-local` の中に空フォルダを
> 作っても親ルールが効いてしまい、Before と After の差が出ない。デモが成立しなくなる。

確認（どれも「なし」であること）:

```bash
ls ~/.claude/CLAUDE.md ~/CLAUDE.md ~/work/CLAUDE.md 2>&1
```

## 6. リハーサルのやり方

本番と同じ条件で2回回す。**PART 1 と PART 2 を通しで**やること。

### 開始状態に戻す

```bash
rm -rf ~/work/wp-plain/site1
cd ~/work/wp-local && ./scripts/reset.sh demo -y
```

### 1回目

文書B の PART 1 → PART 2 → PART 3 を上から順に流す。
その際、次を**メモに記録する**（AI の出力は毎回ゆれる）。

**PART 1（素のまま）で記録すること** —— ここが今回の新しい見どころ

- 確認質問で止まったか。止まったなら**何を聞かれたか**
- AI が選んだポート番号
- AI が選んだ管理者ID・パスワード
- イメージタグは何になったか（`latest` か、固定タグか）
- 日本語化されたか（指示していないのでされないはず）
- 所要時間

**PART 2（ルールあり）で記録すること**

- 確認質問なしで最後まで走ったか
- 8080 / admin / password / タグ固定 / 日本語化、すべて満たしたか
- `examples/compose.yml` とどう違ったか
- 所要時間

**PART 3 で記録すること**

- `wp post create` を使ったか、`wp db query` に逃げたか
- 各シーンの実測時間

### 揺れを抑える

記録した差分のうち、毎回起きるものだけを潰す。**ただし PART 1 の揺れは潰さない。**
PART 1 で毎回違うものが出るのは**今日の教材そのもの**なので、そのままにしておく。

潰すのは PART 2 側だけ:

- 構成そのものがぶれる → 親 `CLAUDE.md` に1行足す
- 細かい書き方がぶれる → `examples/` を寄せる（AI は参照する）
- 期待した動きにならない → 定型プロンプトの文言を直す

> `CLAUDE.md` は短く保つ。解説を書き足さない。増やすほど当日「これ全部読ませてるの？」と
> 見えてしまい、**PART 2 の山場①の説得力が落ちる**（1画面に収まることが効いている）。

### 2回目（まっさらから）

```bash
rm -rf ~/work/wp-plain/site1
cd ~/work/wp-local && ./scripts/reset.sh demo -y
```

`reset.sh` 直後の `demo/` は `CLAUDE.md` 1枚だけの状態になる。
**ここで `ls -a` して本当に1枚だけかを確認する。** `compose.yml` の `./wp:/var/www/html`
バインドマウントで作られたファイルが Permission denied で残ることがある。残っていたら:

```bash
sudo rm -rf ~/work/wp-local/demo/wp
```

ここから本番と同じに流れたら準備完了。

### 保険を録る

2回目が通ったら、**その流れを画面録画しておく**。当日どうにもならなくなったら
これを流して解説する（文書B トラブル対処の最終手段）。

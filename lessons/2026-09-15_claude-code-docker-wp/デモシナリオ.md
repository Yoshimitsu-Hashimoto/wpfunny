wpFUNNY ライブ講座（第1回）／2026-09-15／Zoom 90分

画面共有には `講座テキスト.md` を写す。

**今日の軸（何度でも戻る一文）**
> Local は GUI で「人が」操作する道具。Docker はコマンドで「機械が」操作する道具。
> だから AI に任せられる範囲が段違いになる。

- Docker のメリット説明はしない（前回済み）
- 定型プロンプトは**毎回同じものをコピペ**する。その場でアドリブを書かない
- **プロンプト① は PART 1 と PART 2 で一字一句同じものを使う。これが今日の仕掛け**
- 使ったプロンプトは全部 Discord に貼る、と最初と最後に宣言する

# シーン2｜素のまま指示を投げる

**1. 前振り**
- 「作りたいものだけ書きます」

**2. プロンプト①（定型・コピペ）**

```
このディレクトリに WordPress のローカル環境を作って、ブラウザで開ける状態まで持っていってください。
compose.yml と Dockerfile と .env を作り、コンテナを起動し、WordPress の初期セットアップまで
終わらせてください。終わったらアクセス先の URL と管理者ログイン情報を教えてください。
```

**3. 期待される動き（3〜6分）**
- **確認質問で止まる可能性が高い**（ポート番号、パスワードなど）
- ポート・パスワード・イメージタグを AI が自分で決める
- `latest` タグを使ってくる可能性がある
- 日本語化は指示していないので**されない**

**4. ここで拾うこと（最重要）**

止まったり、勝手に決めたりしたら、**それを指差して言う**。

> 「今、聞かれましたよね。これ、毎案件やりますか？」
> 「このポート番号、僕は指定していません。AI が決めました」
> 「タグ、`latest` になってますね。来月これを実行したら別のバージョンが来ます」

**聞かれなかった場合も拾える**:
> 「今回は聞かれませんでした。でも**次も聞かれない保証はありません**。
> ここが『毎回変わる』ということです」

**5. ブラウザで開く**

```
http://localhost:8080
```

- 動くことは動く。**英語のままのはず**（日本語化を指示していないので）
- 生成された `compose.yml` を開いて見せる

**6. 締めの問いかけ（PART 2 への橋）**
> 「動きました。でも考えてみてください。
> このポート番号、誰が決めましたか。このパスワード、どこかに記録されていますか。
> 明日また作ったら、同じものができますか。
> **案件が1つなら困りません。問題は2件目からです**」

**7. 詰まった時**
- ビルドが長い → 「初回だけです」と言って待つ。PART 2 の前振りを先に話す
- AI が確認質問で止まった → **これは事故ではなく今日の教材**。慌てず「はい、進めてください」
  と答えてから、止まったこと自体を指差して解説する
- エラーで動かない → **それもそのまま見せる**。「下地が無いとこうなります」で PART 2 に繋がる。
  無理に直さない

# トラブル対処

## 1. ポート競合（8080 が埋まっている）

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

- 犯人が分かれば落とす。分からなければ **8081 に切り替える**と宣言してから、
  AI に「ポートを 8081 に変えて起動し直してください」と投げる
- 切り替えたら、以降の URL 読み上げを全部 8081 に直す（ここでよく噛む）

> **PART 1 → PART 2 の移行時は要注意。** シーン3の `docker compose down -v` を忘れると
> 8080 が埋まったまま PART 2 に入ってしまう。**必ず落としてから移動する。**

## 2. イメージ取得に失敗する

- Docker Desktop を再起動 → 再実行。会場 Wi-Fi ならテザリングに切り替える
- 事前 pull 済みなので `docker images` を見せて「イメージは手元にあります」と言い、
  待ちの間に CLAUDE.md の解説（シーン3）を先に回す

## 3. Claude Code の認証切れ

- いったん `claude` を抜けて再ログイン（1〜2分）
- **この間の埋め方**: 正直に言って、CLAUDE.md をエディタで開いて解説に入る。沈黙を作らない

## 4. AI が確認質問で止まった

- **PART 1 なら教材そのもの。** 慌てず指差して解説する
- **PART 2 で止まったら**: 「まだ書き足りないですね」と正直に言う。
  ルールを育てるという話に繋げれば回収できる

## 5. 最終手段

事前に録っておいた成功時の画面録画を流す。

- 場所: デスクトップ（当日朝に配置）
- 言い方: 「ライブでうまくいかないのも含めて実際のところなので、
  先に録っておいたものを見ながら解説します」

**今日の軸（何度でも戻る一文）**
> Local は GUI で「人が」操作する道具。Docker はコマンドで「機械が」操作する道具。
> だから AI に任せられる範囲が段違いになる。

- Docker のメリット説明はしない（前回済み）
- 定型プロンプトは**毎回同じものをコピペ**する。その場でアドリブを書かない
- 使ったプロンプトは全部 Discord に貼る、と最初と最後に宣言する

# シーン2｜構築の一発指示

**1. 前振り**
- 「作りたいものだけ書きます。どう作るかは書きません」
- 「この1回のやり取りで、ブラウザで開ける WordPress まで行きます」

**2. プロンプト（定型・コピペ）**

```
このディレクトリに WordPress のローカル環境を作って、ブラウザで開ける状態まで持っていってください。
compose.yml と Dockerfile と .env を作り、コンテナを起動し、WordPress の初期セットアップまで
終わらせてください。終わったらアクセス先の URL と管理者ログイン情報を教えてください。
```

**3. 期待される動き（合計 2〜4分）**
- `compose.yml` / `Dockerfile` / `.env` を生成（30秒）
- `docker compose up -d --build`（イメージ pull 済みなら 40〜90秒）
- `docker compose exec wordpress wp core install --url=http://localhost:8080 ...`（20秒）
- `wp language core install ja --activate`（20秒）
- URL とログイン情報を日本語で返してくる

待ち時間には次を話す:
- 「今3つのファイルを作って、コンテナを2つ立てています」
- 「僕はポート番号もパスワードも指定していません。全部ルールに書いてあるからです」

**4. 見せどころの一言**
> 「ここまで、**人が一度もクリックしていません**。Local なら今、新規サイト作成ウィザードを
> 3〜4画面クリックしているところです」

**5. 詰まった時**
- ビルドが長い → 「初回だけです」と言って、ルール（CLAUDE.md）の話を先に始めて時間を埋める
- AI が確認質問で止まった → **考えずに「はい、進めてください」と即答**。止まったこと自体を
  「ルールに書き足す対象」として後で触れると自然に回収できる
- `wp core install` が DB 接続エラー → DB の起動待ち。`docker compose ps` を見せてから
  「もう一度 core install を実行してください」と指示（healthcheck があるので通常は起きない）

# やりにくい場面（5分・正直に話すパート）

AI に全部任せられるわけではない、という話を先回りしてする。

1. **表示崩れは伝わらない**
   「CSSが崩れてる」と言っても AI には見えない。スクリーンショットを撮って渡す必要がある。
   結局、目で見る仕事は残る。
2. **初回の pull は待つ**
   今日は事前に落としてあるが、素の状態だと3〜5分かかる。これは AI では縮まらない。
3. **ポート競合**
   8080 が埋まっていると起動しない。`projects.md` でポートを管理している理由がこれ。
   AI は「ポートを変えていいですか」と聞いてくれるが、**どのポートが空いているかは人が管理する**。

> 「AI は速い。けど、目で見ること・待つこと・番号を管理することは人の仕事として残ります」

# トラブル対処

## 1. ポート競合（8080 が埋まっている）

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

- 犯人が分かれば落とす。分からなければ **8081 に切り替える**と宣言してから、
  AI に「ポートを 8081 に変えて起動し直してください」と投げる。
- 切り替えたら、以降の URL 読み上げを全部 8081 に直すのを忘れない（ここでよく噛む）。

## 2. イメージ取得に失敗する

- 症状: `docker compose up` が pull で止まる、`TLS handshake timeout`
- 対処: Docker Desktop を再起動 → 再実行。会場 Wi-Fi なら**テザリングに切り替える**
- それでも駄目なら: 事前に pull 済みなので、`docker images` を見せて
  「イメージは手元にあります」と言い、ネットワーク待ちの間に CLAUDE.md の解説（シーン3）を先に回す

## 3. Claude Code の認証切れ

- 症状: 起動時に認証を求められる、401 が返る
- 対処: いったん `claude` を抜けて再ログイン。ブラウザが開くので通す（1〜2分）
- **この間の埋め方**: 「AI ツールは認証が切れることがあります」と正直に言って、
  そのまま CLAUDE.md をエディタで開いて解説に入る。沈黙を作らない

## 4. AI が確認質問で止まった

- 対処: 考え込まず**即「はい、進めてください」**。デモを止めないことが最優先
- 拾い方: 「今、確認を求められました。これは CLAUDE.md に『ここは聞かなくていい』と
  書けば止まらなくなります。ルールを育てるというのはこういうことです」
  → **事故ではなく教材として回収できる**ので、慌てない

## 5. 最終手段

どうにもならなくなったら、**事前に録っておいた成功時の画面録画を流す**。

- 録画ファイルの場所: デスクトップ（当日朝に配置）
- 言い方: 「ライブでうまくいかないのも含めて実際のところなので、
  先に録っておいたものを見ながら解説します」
- 録画を流しながらでも、シーンごとの「見せどころの一言」はそのまま使える

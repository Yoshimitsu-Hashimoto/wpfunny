# Claude Code × Docker で WordPress ローカル環境を作る

wpFUNNY ライブ講座 第1回／2026-09-15／90分

## 今日の軸

> **Local は GUI で「人が」操作する道具。**
> **Docker はコマンドで「機械が」操作する道具。**
>
> だから AI に任せられる範囲が段違いになる。

---

## 前提の環境

今日のデモはこの環境で動かしています。

| | 必要なもの | 今日の環境 |
|---|---|---|
| OS | macOS（Apple Silicon） | macOS 26.6 |
| Docker | **Docker Desktop がインストール済み・起動中** | v29.8.0 / Compose v5.5.1 |
| AI | **Claude Code がインストール済み・認証済み** | v2.1.272 |
| その他 | ターミナル、ブラウザ | — |

### 確認コマンド

自分の環境でやってみる場合は、まずこれが通ることを確認してください。

```bash
docker compose version     # Docker Compose version v5.5.1
claude --version           # 2.1.272 (Claude Code)
```

`command not found` が出る場合は、そのツールが未インストールか PATH が通っていません。

### Docker Desktop について

- **起動していないとコマンドが全部こけます。** メニューバーのクジラアイコンが
  動いていることを確認してください
- Settings → Resources で**メモリ 4GB 以上**にしておくこと
  （WordPress と MySQL の2コンテナを同時に動かします）

### 使うポート

`8080` を使います。すでに何かが使っていると起動しません。

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN     # 何も出なければ空き
```

> Docker Desktop と Claude Code の導入自体は今日の範囲外です。
> 導入手順は Discord に貼ります。

# PART 1｜素のまま、指示だけで作る

## 1-1. 空のフォルダを作る

下地は何もありません。フォルダを作るだけです。

```bash
mkdir -p ~/work/wp-plain/site1
cd ~/work/wp-plain/site1
ls -a
```

**空です。** 設定ファイルもテンプレートも、何もありません。

```bash
claude
```

## 1-2. 指示を投げる

### プロンプト ①

```
このディレクトリに WordPress のローカル環境を作って、ブラウザで開ける状態まで持っていってください。
compose.yml と Dockerfile と .env を作り、コンテナを起動し、WordPress の初期セットアップまで
終わらせてください。終わったらアクセス先の URL と管理者ログイン情報を教えてください。
```

## 1-3. できたものを見る

```
http://localhost:8080
```

動いています。**動くことは動く。** そこは問題ではありません。

生成された `compose.yml` を開いてみます。

### ここで考えてほしいこと

> このポート番号、**誰が決めましたか？**
> このパスワード、**どこかに記録されていますか？**
> 明日また同じ環境を作ったら、**同じものができますか？**

案件が1つなら、これで困りません。
**問題は2件目からです。** 案件ごとにポートがバラバラ、パスワードがバラバラ、
構成がバラバラ。そして毎回同じことを聞かれる。

# PART 2｜ルールを1枚置く

## 2-1. さっきの環境を片付ける

```bash
docker compose down -v
```

## 2-2. ルールが置いてある場所へ移動する

```
wp-local/                  ← 親。ここに CLAUDE.md がある
├── CLAUDE.md              ← ★これが今日の主役
├── projects.md            ← 使用中ポートの管理表
└── demo/                  ← これから作る子フォルダ
```

親の `CLAUDE.md` を開いて中身を見ます。1画面に収まる短さです。

| 書いてあること | 中身 |
|---|---|
| ポート割当 | `8080` から順に払い出す。表で管理する |
| イメージ | タグを固定する（`latest` は使わない） |
| 管理者 | `admin` / `password` |
| 言語・時刻 | 日本語、`Asia/Tokyo`、日付は `Y年n月j日` |
| **既定プラグイン** | **All-in-One WP Migration / Wordfence を入れて有効化** |
| WP-CLI | `docker compose exec wordpress wp` 経由で使う |
| 確認の要否 | **削除以外は聞かずに実行してよい** |

さっき AI が聞いてきたこと、勝手に決めたこと。**その答えが全部ここに書いてあります。**

## 2-3. 子フォルダも、会話で作らせる

ここもコマンドを打ちません。**親フォルダで `claude` を起動して、頼みます。**

```bash
cd ~/work/wp-local
claude
```

### プロンプト ⓪

```
demo という案件の環境を 8080 番で作ってください。
```

これだけです。AI はルールに従って、こう動きます。

| | AI がやること |
|---|---|
| 1 | `8080` が空いているか確認する（埋まっていたら止まる） |
| 2 | `demo/` フォルダを作る |
| 3 | テンプレートから `demo/CLAUDE.md` を書き出す |
| 4 | **`projects.md` の管理表に1行追加する** |

4番に注目してください。**ポートの管理表まで更新されています。**
「どのポートを誰が使っているか」を人間が書き忘れる問題が、ここで消えます。

### できたものを確認する

いったん抜けて、できた子フォルダに入ります。

```bash
cd demo
ls -a
```

`CLAUDE.md` が1枚だけ。中身は4行です。

```markdown
# demo ローカル環境

- ホストポート: 8080
- URL: http://localhost:8080

上位ディレクトリ `wp-local/CLAUDE.md` のルールに従う。
```

compose.yml はありません。**PART 1 と同じ、空っぽの状態です。**

このフォルダで、あらためて `claude` を起動します。
今度は親のルールに加えて、**この子フォルダのルール（ポート8080）も読み込まれます。**

```bash
claude
```

## 2-4. まったく同じ指示を投げる

### プロンプト ①（PART 1 と一字一句同じ）

```
このディレクトリに WordPress のローカル環境を作って、ブラウザで開ける状態まで持っていってください。
compose.yml と Dockerfile と .env を作り、コンテナを起動し、WordPress の初期セットアップまで
終わらせてください。終わったらアクセス先の URL と管理者ログイン情報を教えてください。
```

## 2-5. 何が変わったか

| | PART 1（素のまま） | PART 2（ルールあり） |
|---|---|---|
| 確認質問 | 聞かれる | **聞かれない** |
| ポート | AI が決める | **8080（表で管理）** |
| 管理者 | AI が決める | **admin / password** |
| イメージ | `latest` になりがち | **タグ固定** |
| 日本語化 | 指示しないとされない | **される** |
| タイムゾーン | UTC のまま | **Asia/Tokyo** |
| 日付表示 | `2026/09/15` 形式 | **`2026年9月15日`** |
| プラグイン | 入らない | **2つ入って有効化済み** |
| 再現性 | 毎回変わる | **毎回同じ** |

プロンプトは**1文字も変えていません。**

## 2-6. 今日いちばん持ち帰ってほしい考え方

> **「何を作るか」はプロンプトに。**
> **「どう振る舞うか」は CLAUDE.md に。**

プロンプトが3行で済んだのは、AI が賢いからではありません。
**残りをファイルに書いてあるから**です。

そして CLAUDE.md は、**次の案件にそのまま持っていけます。**
一度書けば、2件目以降はこの3行だけで済む。ここが資産になります。

### 「うちの標準セット」を書いておける

プラグインの行に注目してください。

```
All-in-One WP Migration / Wordfence を入れて有効化する
```

新規案件のたびに管理画面から検索してインストールして有効化、をやっていませんか。
**それを1行書いておけば、以後は勝手に入ります。**

タイムゾーンも日付フォーマットも同じです。
「毎回やっている地味な初期設定」を全部ここに集めておける。
**これが「資産」の意味です。**

# PART 3｜会話で触る

ここからは、できた環境を操作します。

## 3-1. まずは見るだけ

### プロンプト ②

```
この WordPress に今どんなユーザーがいるか教えてください。あと投稿は何件ありますか。
```

> 管理者1名（admin）、投稿は1件（Hello world!）です

裏では WP-CLI がこう動いています。

```bash
docker compose exec wordpress wp user list
docker compose exec wordpress wp post list --format=count
```

管理画面で言えば「ユーザー一覧」と「投稿一覧」を開く操作です。
でも **画面のどこにあるかを知らなくていい。** 日本語で聞いただけです。

## 3-2. 書き込む

制作でよくあるやつです —— 表示確認用に記事が10件ほしい。

### プロンプト ③

```
表示確認用に、ブログっぽいダミー記事を10件作ってください。
カテゴリを3つ作って振り分け、本文も200文字程度でそれらしく書いてください。公開状態にしてください。
```

カテゴリ3つと記事10件。**本文まで書かれています。**
Lorem ipsum ではなく、読める日本語です。

管理画面でやると、これを10回繰り返すことになります。

```
新規追加 → タイトル入力 → 本文入力 → カテゴリ選択 → 公開
```

> 10件で2分。**100件でも同じプロンプトです。**
> GUI は人の手の速度で頭打ちになる。コマンドは件数が変わっても手間が変わらない。

## 3-3. 確かめる

### プロンプト ④

```
今ある記事のうち一番本文が長いものを探して、内容を3行で要約してください。
```

### プロンプト ⑤

```
編集者権限のユーザーを1人追加して、今のユーザー一覧を見せてください。
```

## 3-4. 答え合わせ

ブラウザに戻ってリロード（⌘ + Shift + R）。

- 投稿一覧に **10件**
- ユーザー一覧に **editor01**

### PART 3 の結論

> 今やったことは全部、**管理画面のどこかを開く操作に相当します。**
> ユーザー追加も、記事作成も、一覧の確認も。
>
> コマンドがあるから、それを会話にできた。
> **これが Docker を使う一番の理由です。**

# PART 4｜AI に任せきれない場面

正直な話もしておきます。全部が速くなるわけではありません。

### 1. 表示崩れは伝わらない

「CSSが崩れてる」と言っても AI には**見えていません**。
スクリーンショットを撮って渡す必要があります。目で見る仕事は残ります。

### 2. 初回のダウンロードは待つ

イメージの取得は素の状態だと3〜5分かかります。これは AI では縮まりません。

### 3. ポートの管理は人がやる

8080 が埋まっていると起動しません。
AI は「変えていいですか」と聞いてはくれますが、
**どのポートが空いているかを知っているのは人だけ**です。
`projects.md` で表を管理しているのはこのためです。

> AI は速い。
> けれど、**目で見ること・待つこと・番号を管理すること**は人の仕事として残ります。

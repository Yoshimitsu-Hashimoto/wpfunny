## 決定事項

### 「4パターン」の枠組みは廃止
当初はドメイン移管も絡めて4パターンとする想定だったが、講座構成として
**サーバー移転とドメイン移管を明確に分ける**方針にしたため、4パターンという括りをやめる。

- **サーバー移転**は「Webサーバーは移転する」を前提とし、
  軸は**メールサーバーを移転するか／しないか**の1本のみ。
- **ドメイン移管**は独立した章（2章）で扱う。
- 両方を同時にやるケースは、**複合版として別章**で流れと手順を解説する。

### サーバー移転は「丸ごと引っ越し」がデフォルト
メールを使っていない場合は、遠慮なく**ネームサーバーごと新サーバーへ丸ごと移す**。
移転後にメールが必要になったら、新サーバーで作り始めればよい。

したがって章の組み立ては「4パターンから選ぶ」ではなく、
**基本は丸ごと → 例外的にWebだけ移すのはどんなときか**という順にする。
「Webだけ移す」を選ぶのは、旧サーバーのメールを使い続ける必要がある場合か、
外部メールサービス（Google Workspace等）を使っている場合に限られる。

### 知識編（1章・2章）と手順編（3章・4章）の書き分け
- **知識編**＝机上での解説。AuthCodeの取得を含め、**一通りの手順の流れは知識編で押さえきる**。
  読めば全体が理解できる状態にする。サーバー移転・ドメイン移管とも同じ方針。
- **手順編**＝実際の管理画面に沿ったスクショつきの操作解説。

## 今後やりたいこと（着手時期未定）

### ネームサーバー切り替えによるDNSレコード消失（★重要・要追加）

**核心**: ネームサーバーを切り替える＝**ゾーンを丸ごと差し替える**こと。
レコードが削除されるのではなく、旧ゾーンを誰も参照しなくなる。
新サーバーのゾーンはドメイン追加時に自動生成された初期状態（A・www・MX・SPFだけ）なので、
旧サーバー側で足していたレコードは全部無かったことになる。

**事故るレコード（実害の大きい順）**
1. **MXレコード** — Google Workspace / Microsoft 365 利用時。切り替えると新サーバーを指すMXに置き換わり全社メールが停止。Webは正常に見えるので原因に辿り着きにくい。
2. **サブドメインのA / CNAME** — 件数最多。`shop`→Shopify/BASE、`blog`→外部ブログ、`lp`・`stg`→別サーバー、`mail`→Webメール。新サーバーは存在を知らないのでサブドメインが全滅。メインサイトだけ見て成功と判断すると見逃す。
3. **TXT（SPF / DKIM / DMARC）** — 消えてもメールは届くが**迷惑メール判定される**。発覚が数週間後になる最悪パターン。
4. **所有権確認用のTXT / CNAME** — Search Console、Workspaceのドメイン確認、SendGrid・Mailchimp等のカスタムドメイン。認証が外れてサービスが止まる。
5. **CAAレコード** — 残っていると新サーバーでSSLが発行できない／消えると発行元制限が外れる。稀だが原因が分かりにくい。

**気づきにくさの順序**（ここが解説の核）

| 症状 | 発覚までの時間 |
|---|---|
| メインサイトが落ちる | 即座 |
| サブドメインが落ちる | 数時間〜数日 |
| メールが届かない | 半日〜数日 |
| SPF欠落で迷惑メール化 | 数週間〜、気づかないことも |

→ 伝えたい核は **「サイトが表示された＝移転成功、ではない」**。

**洗い出し方法と限界**
- ゾーン転送（AXFR）は通常禁止されているため、**外部から既存サブドメインを列挙する手段はない**。
  `dig` で確認できるのは自分が知っているレコードだけ。
- したがって **旧サーバーの管理画面でDNSレコード一覧を開いて全部控えるのが唯一確実な方法**。
  `dig` は切り替え後の差分確認などの補助に留まる。

**構成上のポイント**
- 「Aレコードだけ書き換える」方式ならこの事故は起きない（既存ゾーンをそのまま使い1行だけ変えるため）。
  つまり**既存ゾーンが複雑な場合は、丸ごと引っ越しよりAレコード方式のほうが安全**という判断軸が生まれる。
  「丸ごとがデフォルト」は、ゾーンがシンプルな場合の話だと補足が要る。
- 切り戻しは可能（NSを旧に戻せば旧ゾーンが復活する）。ただし旧サーバーを解約していたら戻せない。

**配置案**: 独立した章にするか、DNSレコード詳細解説の章の中の節にするか。
ただし事故の中心なので、**1章の「よくある失敗やトラブル」では一言だけ触れて「詳細は後の章」と予告**しておきたい。

### DNSレコードの詳細解説（参考情報の章）
5章よりさらに後ろに、**参考情報レベル**で各DNSレコードの詳細を解説する章を設けたい。

想定する内容:
- Aレコード / AAAAレコード
- CNAMEレコード
- MXレコード
- TXTレコード（SPF・DKIM・DMARC、所有権確認）
- NSレコード
- CAAレコード / SRVレコード など

位置づけ: 本編の理解には必須ではないが、実務で管理画面を触るときに効いてくる補足知識。
本編を軽く保つために、あえて分離する。

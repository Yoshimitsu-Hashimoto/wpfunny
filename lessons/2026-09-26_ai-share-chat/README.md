## ① 全体の仕組み

### ディレクトリ構成

- 1案件 = 1フォルダ + CLAUDE.md。`~/work` の下に案件ごとのフォルダを置き、ルールは CLAUDE.md に書く
- セッション名に【案件名】を自動で付ける。セッションが増えても迷わない
- フリーな相談は `~/work` 直下で始め、案件になったらフォルダを作って移動する

### ローカルとクラウドの使い分け

- ローカル: Docker で動かす WordPress、本番の DB ダンプ、実データを入れた複製環境
- クラウド: freee、Gmail、Notion、カレンダーは claude.ai のコネクタでつなぐ。パスワードなどの認証情報はローカルに置かない
- Remote Control を使えば、スマホから作業の続きを確認できる

### GitHub でローカルとクラウドをつなぐ

ローカル ⇄ GitHub ⇄ クラウドとスマホ。どこからでも同じ状態から続きができる。

- 案件事例A: 本番テーマの控えを GitHub で管理
- 案件事例C: 自分用のリポジトリ（仕様・テスト計画）を作成。提供されたリポジトリは読むだけにして、push 先を無効化している（AI に事故らせない工夫）
- wpFUNNY: 講座の教材（このリポジトリ）も GitHub で管理

## ② WordPress 案件での活用

環境づくりから影響確認、バグ修正、デプロイまで AI に任せている。

- wp-local: 「◯◯の環境を 8084 で作って」の一言で、ポートの空き確認、フォルダ作成、CLAUDE.md の用意、ポート一覧表への記入までやる
- 案件事例A:
    - 本番テーマの控えをローカルで動かし、本番の DB を何度でも入れ直せる
    - プラグインを更新したときの影響確認
    - カテゴリを増やす作業で、見積もりメールの下書きまで作った
- 案件事例B:
    - テストで見つかったバグを PR 単位で直し、確認してからマージ
    - デザインチェック用のスクリーンショットを撮らせる
    - クライアントの動作確認結果をまとめさせる
    - MU プラグインの自動デプロイ（push すると本番に反映）
- 失敗から作ったルール: イメージのタグは latest を使わない、DB のポートは外に公開しない

## ③ 開発以外の仕事での活用

- freee: コネクタ経由で見積書と請求書を作成。書き込む前に必ず内容を見せて確認させる
- Slack の稼働打刻 Bot（GAS）: 実装計画を AI と一緒に作った
- 案件の見積もり検討
- Figma のデザインから仕様をまとめる
- Discord の告知文
